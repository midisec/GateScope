# 一年历史缓存、自动回放与事前点位预测（V3）

模型：`structure-study-3`。迁移：`0025_annual_structure_history`。本功能属于行情研究，不改变下单、止盈止损、账户权限或交易证据。

## 页面入口与含义

行情 → 形态与波浪 → **自选历史同步进度**：按币种及周期展示一年目标、本地覆盖率、缺口、回放队列及游标，24 行分页，10 秒刷新。仅展示当前用户自己的自选；底层公开 OHLC 数据跨用户复用。

“当前结构”卡片展示下一段候选区/条件目标。选中结构后可展开“预测点位与形成条件”，查看具体价格、确认所需收盘次数、首次目标验证、实际枢轴和发布时间。“候选档案”保留所有节点和原始图；旧模型没有预测字段时明确说明，绝不补写事前预测。

“历史表现”显示实际回放范围和一年覆盖率。回放完成不等于数据覆盖一年：上游未提供的历史仍属于缺口。报告里的 `partial` 表示**回放任务**尚未结束，`metadata.missing_bars` 表示**数据覆盖**尚不完整，两者不能混用。

## 一年窗口与数据来源

固定滚动 365 天，UTC 对齐，仅包含已收盘 K 线。不是闰年/日历年的模糊范围。

| 周期 | 每币种目标根数 | 超出普通接口范围的来源 |
|---|---:|---|
| 1m | 525,600 | 官方 1m 月文件 |
| 5m | 105,120 | 官方 5m 月文件 |
| 15m | 35,040 | 同交易所完整 5m 聚合 |
| 30m | 17,520 | 同交易所完整 5m 聚合 |
| 1h | 8,760 | 普通接口；适配器也支持官方 1h 文件 |
| 4h | 2,190 | 普通接口；适配器也支持官方 4h 文件 |
| 8h | 1,095 | 普通接口；历史文件使用完整 4h 聚合 |
| 1d | 365 | 普通接口；适配器也支持官方 1d 文件 |

自选订阅函数已扩展全部 8 周期；市场 worker 持续扫描去重订阅，因此新增币种无需人工启动任务。移出自选只停订阅，不删历史。365 天以前已存在的数据也不自动删除。

使用 [Gate 官方历史下载规范](https://www.gate.com/developer/historical_quotes) 的固定域名 `download.gatedata.org`、固定路径模板；不接收密钥或任意 URL，不跟随重定向。文件列顺序为 timestamp、volume、close、high、low、open，程序转换为标准 OHLCV 后校验。

2026-09-10 只读实测：2025-09 BTC_USDT 的 1m、5m、1h、4h 官方文件可下载；原生 15m 文件返回 404。普通合约接口的一年前 1m 请求返回 400，同期 1h 返回 200。当前月份文件尚不可用，可能造成“普通接口最早时间”与“已发布月文件”之间的暂时缺口。上市不足一年的标的不伪造上市前数据。

- 每轮先处理最多 16 个实时订阅，再处理最多 2 页历史，每页最多 900 根；实时数据优先。
- 本地月文件跨周期复用（15m/30m 共用 5m），最多 16 MiB 压缩/32 MiB 展开，逐行读取，下载超时、体积和磁盘余量有界；临时文件校验后原子提升。
- 聚合要求每根小周期齐全且连续；OHLC 首开、最高、最低、末收，成交量求和。缺一根就舍弃该聚合 K 线，不插值。
- 归档仅填空缺，不覆盖 REST 修订；记录 `GATE_MONTHLY_ARCHIVE`、`AGGREGATED_COMPLETE_SOURCE` 等质量标记。API 与原图证据继续按快照时的 K 线修订取数。
- 缺口由数据库窗口函数计算，服务端游标逐段读取，不把一年 52 万个时间戳装入 Python 集合。
- 未发布月份存入 `market_history_deferred`，6 小时后重试。跳过该缺口，继续更早月份，不能卡在第一处 404。缺口始终保留在 `missing_bars` 中。
- HTTP 429 使用 Retry-After，并持久化退避；没有无限立即重试。磁盘剩余不足 2 GiB 时暂停历史下载，不停实时轮询。

## 自动回放与断点

复用现有 strategy worker，不增加常驻进程。每 30 秒检查自选缓存，已就绪或明确存在上游缺口且不少于 60 根时自动排队。全局最多 8 个回放任务，优先日线/小时线；后台轮转处理，不依赖网页打开。

首次回放固定 `snapshot_at` 和一年时间边界。SQL 只取该快照时已经落库、已收盘的最新修订；每片最多 64 根、约 2 秒计算预算，识别窗口仅保留 480 根。识别仍逐根前缀推进；缺口截断识别窗口并将活跃候选标记为观测中断，不把不同缺口两侧拼接成形态。

事务同时提交游标、480 根窗口、有限活跃状态、不可变候选节点、阶段和收益投影。中断回滚当前片，重启继续。热状态只保留活跃及最近 480 根内结束的候选；历史失效与预测节点存在数据库中，不因热状态清理而删除。输入摘要是按消费顺序连接时间、修订和 payload hash 的哈希链。

统计投影：

- `market_structure_stages`：每候选/进入阶段一行，固定阶段时间、独立抽样和初始概率；终态及预测结果是可重建投影。
- `market_structure_returns`：每证据/观察期一行。首次识别后下一根开盘入场，5/10/20/50 根收盘退出，假设双边成本 0.10%。方向中性、重叠、尾部未完成、数据中断分别记录。
- 热状态仅保留未来最多 50 根的待评估收益样本。报告由 SQL 分组汇总 260 个完成统计单元和 208 个收益单元，不保留全年的 Python 交易列表。
- 完成后保留有界断点。15 分钟检查周期到达且有新增已收盘数据时追加回放；旧时间区间新增/修订数据则创建新批次完整重放，旧节点不覆盖。
- `market_pattern_reports` 保存批次首次完整报告；`market_pattern_report_versions` 不可变追加各次增量报告。当前界面读最新投影；历史候选批次是持续追加的事件账本，不应把批次创建时间误作所有节点的实测时间。

收益重叠样本在信号出现时固定剔除，不能等看到收益后挑样本。完成率为确认 /（确认 + 失效 + 到期），待定和观测中断不进入分母。至少 20 个有效样本才输出区间，采用 [Wilson 区间](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm) 和多重比较校正；相关样本和模型选择仍可能使区间失真。

## 预测的价格约束与历史修正

价格候选区不是置信区间，匹配评分不是胜率，确认率也不是目标价命中概率。

双顶/底的第二枢轴候选区采用与完整检测器一致的颈部 ATR 容差（±0.75 ATR）。形成中失效边界同步纳入容差，修复“稍高于第一顶就提前否决有效双顶”的不一致。进入价格区之后仍需几何、匹配阈值和右侧 4 根确认，不保证一定形成。

波浪采用 [标准推动浪约束](https://www.elliottwave.com/waveopedia/impulse/) 与 [常见斐波那契关系](https://www.elliottwave.com/waveopedia/fibonacci-relationships/) 作为明确的研究假设：

- 0/1/2 已知：预估第 3 浪，须越过第 1 浪；不提前宣称整个五浪已完成。
- 已知第 3 浪：第 4 浪回撤区不得进入第 1 浪区域。
- 已知第 4 浪：第 5 浪必须越过第 3 浪；若第 3 浪短于第 1 浪，则第 5 浪不得更长于第 3 浪。
- ABC/完整周期：分别预估 B 或 C 的下一段目标，限制 B 回撤比例、C 相对 A 的延伸及周期硬约束。
- 已形成且有单侧方向：给出满足突破前提后的量度目标。方向不确定或比例区间与硬约束冲突时明确“不发布点位”，不硬选一个价位。

历史修正：同模型、币种、周期、形态、阶段、已知腿数，取此前独立抽样且已完成下一段的最近最多 256 例。剔除自身、同一时点/未来结论、超过一年及违反当前硬约束的比例。至少 20 例才将历史中位数与理论中心收缩组合，历史权重 `min(0.75, n/(n+40))`。候选区仍是理论允许区，不包装成经过检验的预测区间。已完成下一段的比例样本是条件样本，不能用它们单独计算成功率；失败另在完成统计和首次触价统计中展示。

新枢轴推进产生独立修订，保存 `first.forecast`、`latest.forecast`、`pre_formation_forecast` 和实际后续枢轴。不得因已看到最终成功价格而修改旧目标。形成后的新目标明确标记为条件目标，不冒充形成前预测；条件目标目前不计入首次形成目标触价统计。

仅统计发布之后的价格触及。相同 K 线同时触价和失效记为先后不明；数据缺口记为中断；终止前未触及记为未达到。实际枢轴发生时间早于预测发布但晚些才确认时，标明不能算事前命中。触及原目标并不代表整个形态成功，形态最后失效仍进入失败统计。

## 容量与部署边界

当前机器约 3.7 GiB RAM，无 swap；改造时可用内存约 225–360 MiB，因此验证、构建串行执行。一币种所有周期一年共 695,690 根，月文件和数据库历史会持续占用磁盘，候选不可变节点另计。未来推广到大量币种/用户时需要容量预算、数据库分区与任务分流，不能把当前单机宣传成无限规模。

第一次 1m 年度逐根识别可能需要较长时间，具体以进度为准。完成代码部署不代表一年数据和所有样本已生成；上游未发布数据无法由本系统补造。

部署顺序：备份 PostgreSQL → 迁移 0025 → 创建 `data/market-archives`（0700）→ market service 添加精确 ReadWritePaths → 重启市场/策略/API → 原子发布前端 → 校验服务、覆盖率及队列。旧月文件和历史节点不删除；回滚应用前须停新模型研究，不应盲目 downgrade 删除研究投影或版本报告。

验证覆盖：年目标计算、月度 404/429/重定向、完整小周期聚合、缓存重用、超过 8,000 根分片回放、进程重启、增量追加、历史修订触发新批次、API 最小权限、自选归属隔离、首次预测冻结、未来样本排除、波浪硬约束、同根歧义、失效留档和桌面/手机交互。
