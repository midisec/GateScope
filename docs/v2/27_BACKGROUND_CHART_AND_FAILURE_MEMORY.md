# 后台图表快照与实时失败样本记忆

日期：2026-09-11（Asia/Shanghai）。识别模型保持 `structure-study-3.1`，数据库升级至 `0029_background_chart_cache`。本次不新增策略，不启用实盘。

## 实际问题

原先自选八周期采集已独立于浏览器运行，生产 BTC / ETH 的 16 个订阅持续更新；慢点主要是打开图表时重复构造最多 1500 根领域对象、计算摘要及传输大段未压缩 JSON，浏览器的内存缓存又会在页面重载后丢失。历史补录、目录请求与实时采集共用一个循环，上游历史请求较慢时也会拖延最新行情。

实时结构事件此前已有不可变档案，但没有同步写入供历史参考查询使用的阶段投影。实时预测主要参照回放，且跟踪器每次处理新 K 线时可能用回放 checkpoint 覆盖实时学习状态。因此“保存了失败”不等于“后续判断参考了失败”。

## 数据和执行边界

- 行情 worker 按数据库自选/策略订阅采集，不依赖在线会话；新增自选继续自动覆盖 1m、5m、15m、30m、1h、4h、8h、1d。历史目标仍为一年，缺口不伪造填充。
- 同一进程内，实时采集与维护任务分两条执行通道；维护最多一个线程，承担有界历史补录、目录刷新和原有数据源测试队列。连接池仍最多 4 条。共享数据库退避，429 不无限重试。
- `market_chart_snapshots` 是可重建的公共行情读模型，不是交易事实。行情写入与 generation 失效标记在同一事务；后台构建最多 1500 根已收盘 K 线，发布时核对 generation。构建期间修订到达则拒绝旧结果；未到可见时间的修订不能被当成已经构建完成。
- API 只读已就绪快照，标记 `read_source=BACKGROUND_SNAPSHOT`；未就绪、有修订、指定历史范围或超过 1500 根时回到规范行情查询。未收盘 K 线、时效状态独立实时读取，指标仍只计算已收盘数据。
- 浏览器按用户/工作区隔离保存最多 6 组、每组 480 根的公共 OHLC 预览，24 小时过期。重载可先展示，再请求完整 1500 根；网络校验前显示缓存状态。失败保留预览，恢复后修复缺口。没有保存凭据，也不能据此下单。
- Nginx 仅对 HTTPS `/api/v2/bars` 增加 JSON 压缩，不开启响应缓存，不改变认证；认证和配置 JSON 不做全局压缩。80 端口仍仅服务 ACME，其他请求 444。

## 失败如何进入下一次判断

1. 每次实时生命周期变化，在同一事务中追加不可变事件，并更新可重建的 `market_structure_stages`。迁移从既有 RECORDED 日志回填，不能修改原事件或首次预测。
2. 后续同币种、同周期、同模型、同形态、同阶段、同评分桶的历史参考，合并当前回放与实测。相同候选 ID 以实测优先，仅计算一次。
3. 只采用本次预测之前已结束、过去一年内的样本；确认是成功，失效和到期是失败。尚未结束、未来才知道结果、当前候选自身及 CENSORED 不计成败；跨来源再作保守的时间重叠排除。
4. 结果返回实测/回放数量、失效/到期数量及最多 3 个可查询失败案例；数据库聚合计数，不向 Python 加载全年明细。
5. 首次预测仍冻结在候选的原始阶段记录中；当前历史参考随新结果增加而变化，不反写首次概率和点位。实时学习状态仅一次性补入历史种子，不再每轮覆盖。
6. 检测到不在热内存中的候选时，批量检查不可变终态日志。同一身份已结束就不重新准入；真正不同锚点的后来结构仍可成立，不能为了去重删除不同候选。

页面入口：行情图表 → 形态与波浪。形成中/已形成卡片显示来源与失败计数；选中结构后展开“历史失败案例”，可以打开原图和事件时间线。所有候选的完整记录仍在“候选档案”中，热窗口移除不等于删除档案。

这里的“历史确认率”是结构生命周期条件成立的比例，不是交易盈利率。有效样本不足时不输出置信区间；加入失败样本可能降低确认率，这应如实展示。跨来源保守排重可能减少有效统计样本，但不减少检测和档案中的候选数量。没有独立标注集或新的样本外交易验证，不能宣称预测准确率提高了某个百分比。
