# 中文合约与上市后历史同步修复

日期：2026-09-12。范围：修复龙虾_USDT 自选历史加载；不修改交易配置、识别模型、通知规则或原始事件。

## 原因与修复

1. 官方中文合约能通过实时 REST 加载，但归档下载器仅允许 ASCII 名称。现在支持原始 Unicode 字母、数字和下划线，URL 文件名按路径段编码；仍拒绝路径穿越、控制字符、百分号等不安全输入，固定官方域名且禁止跳转。缓存文件不重复下载，不覆盖已有 REST 修订。
2. 目标默认仍为过去一年，而非无限全历史。可信 Gate 合约 `create_time` 可将目标截断到上市所在周期；首根不足完整周期的真实 K 线仍保留。已有更早有效缓存只扩大范围，不能根据最早缓存猜测上市日期。无效、未来或未知元数据保守回退一年。
3. 历史下载失败不再阻塞已缓存样本的回放。保持至少 60 根、8 个排队/运行任务、30 秒调度检查、15 分钟冷却和有限失败恢复；运行中的快照不中途重置。补齐更早历史后另建回放上下文，旧原始事件和报告继续保留。
4. 同步进度分别显示有效目标、实时健康和样本回放；新合约明确标注“自上市起、上市前不计缺失”。永久格式拒绝使用独立错误码与 24 小时退避；页面不再一律承诺失败后自动恢复。
5. 进度查询读取后台持久化的同一份分子、分母快照，附带 `coverage_asof`；范围待刷新时保留上一份完整统计，不混用旧数量和新目标。不再每次打开弹窗重数百万根 K 线。未完整覆盖的比例向下保留两位，不将 99.99% 四舍五入为 100%。
6. 官方月度文件确有零散缺根，单次查询最多 900 个目标槽位，将其中最多 450 段真实缺口批量保存，避免每个缺口占用一个调度周期。退避区间一次排序合并并使用二分查找，缺口游标仍然流式读取；缺口不会从缺失数量中抹除。
7. 跨月归档请求仅能证明实际读取月份的缺失，空结果现在仅延期该月份内的查询范围，不能把未读取的上一个月也阻塞。聚合仍要求完整且连续的源 K 线，不用缺根拼接出虚假完整周期。

公共函数 `adapters/market_history_bounds.history_bounds` 供下载、回放和进度使用；元数据和较早缓存均遵循评估时点的可用性约束。下载与研究计数排除错位 K 线，不用补零生成假历史。尚未出现已收盘上市周期的新合约暂保留一年待同步状态，避免数据库非零目标约束下宣称虚假的完成；首次周期收盘后正常裁剪。
