# 历史形态样本、逐根回放与原始判断

日期：2026-09-12（Asia/Shanghai）。模型版本仍为 `structure-study-3.2`，本次不放宽形态规则，不重置历史，不修改交易授权。

## 1. 生产诊断

历史并非没有形态。修复前生产库的同版本年度报告已有如下结果（约 15:48 的快照）：

| 币种 / 周期 | 已识别候选 | 已确认后 20 根收益有效样本 | 有有效收益的形态类别 |
| --- | ---: | ---: | ---: |
| BTC / 1h | 3,688 | 794 | 28 |
| ETH / 1h | 3,954 | 806 | 28 |
| BTC / 4h | 980 | 196 | 21 |
| ETH / 4h | 991 | 194 | 24 |
| BTC / 1d | 107 | 26 | 14 |
| ETH / 1d | 119 | 25 | 14 |

候选总数不是独立交易数；收益样本也不是形态确认概率的分母。不能将不同周期、阶段、收益持有期相加来制造更大的胜率样本。

发现的问题：

1. 当前结构接口把 `CONFIRMED`、`INVALIDATED` 等终态直接传入只支持 `FORMING` / `FORMED` 的统计函数，得到默认零样本。例如 ETH 1h 杯柄的首次预测已有 171 个样本，当前卡片却显示 0。
2. 页面将“未知”默认显示为 0；形成统计默认选择 `FORMING`，但当前 28 类中仅 8 类实现形成中预判，其余类别天然没有这个阶段。
3. 实时预测只在首次启动时导入历史预测训练样本；后续后台补出的已完成波段没有继续补入。
4. 回放计算异常会丢弃进度并从头计算；单页 64 根的旧 SQL 计划还会排序约 250,201 行，拖慢年度分钟线回放。

## 2. 时间口径与不变量

历史回放和实时通道继续调用同一 `structure_lifecycle.observe()` 引擎。每根已收盘 K 线仅使用该时刻可见的前缀窗口，转折点必须已被确认；不将后续走势放入识别窗口。

按原规则依次追加形成中、已形成、突破确认、失效、过期或截尾事件，持久化不可变事件日志和可重建阶段/收益投影。失败不删除，不用今天的几何形状覆盖原图。历史补录数据标记为回放证据，不冒充当时线上实际发出的信号。

当前卡片新增独立的 `historical_reference` 展示投影：

- 原记录存在 `FORMED` 时，取原形成阶段；否则取原 `FORMING` 阶段。
- 只取相同模型、币种、周期、形态、阶段、原始评分组的案例。
- 案例须在原阶段时间之前已结束，排除自身、未来结果、重叠与待定/截尾案例；实测和回放同一候选去重，实测优先。
- 失效和过期纳入失败分母。确认率不等于净盈利概率。
- 原始 `initial_prediction`、首次目标预测和历史图完全不改；晚到回放仅显示为“回放补充对照 · 非当时预测”。原始零样本保留，不能事后改成当时已知。

接口状态区分：`READY`（有同类有效样本）、`NO_MATCHING_SAMPLES`（真实零样本）、`HISTORY_NOT_READY`（投影未就绪）、`STAGE_UNAVAILABLE`（原阶段信息不足）。后二者的 `sample_count` 为 null，不伪装为零。

## 3. 后台与交互修复

- 每个新收盘增量合并同版回放中已完成的目标训练样本，按候选/结束时间去重、实测优先，每个训练分组最多 256 条；预测签发时仍严格过滤未来样本。
- 计算切片使用数据库保存点，异常回滚整个切片的事件、投影和进度；保留上一成功游标。同版本可续跑异常至多自动恢复 3 次，避免无限重试。
- 取下一有效开盘时间后，仅在 `limit × 周期` 的小时间窗内按修订排序；同一 SQL 快照保留 `available_at` / `created_at` / `close_time` 限制。允许缺口短页，不跳过未返回 K 线，不增加全表索引。
- 当前结构和历史面板分别显示历史识别总量、当前阶段/持有期有效收益样本、重叠排除、待定及回放进度。
- 完成统计默认已形成；没有形成中识别能力的类别显示“不支持”，不显示虚假的 0% / n=0。
