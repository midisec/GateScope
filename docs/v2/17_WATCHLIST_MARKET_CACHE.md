# 自选行情持续采集与缓存验收

日期：2026-09-09。数据库版本：`0021_market_cache_sync`。范围为公开行情采集、缓存、研究读取与网页展示；不启用实盘、不改写历史回测，不包含逐笔 WebSocket 撮合行情。

## 本轮排查与修复

| 原问题 | 实现 |
| --- | --- |
| 新订阅只取约 500 根，之后只追最新，不补足研究历史 | 自选自动维护 8 个周期，最近窗口目标 8000 根，按缺口向前分页补齐 |
| 默认漏采 30m / 8h | 统一为 1m、5m、15m、30m、1h、4h、8h、1d；现有活跃告警订阅仍保留 |
| 重试、目录刷新拖住全部币种 | 最新数据优先，独立失败退避，目录失败不阻断已有订阅；长工作周期内更新心跳 |
| 浏览器关闭后以为停止采集 | systemd 原有 market worker 持续写入本机 PostgreSQL，与网页是否在线无关 |
| 只显示收盘价，当前走势无法更新 | 单独保存形成中的 K 线，网页标明未收盘；绝不写进已收盘证据表 |
| 切换空白、慢请求重叠、断网静默 | 有界浏览器缓存、单请求在途、旧请求取消、保留缓存并标记延迟、联网和前台恢复自动重取 |
| 每 5 秒重复传输整段历史 | 首次取 1500 根，稳定后每次取最近 8 根并按时间和版本合并；每 60 秒全量校正，长断档或恢复前台立即全量 |
| 手机自选价格与移除按钮重叠 | 为移除按钮留独立位置；图表初始可见范围随宽度调整为约 60–180 根，刷新保留缩放 |
| 发布时清空静态目录导致启动失败 | 独立临时目录构建，资源先发布，index 原子替换；保留旧哈希资源供已打开页面使用 |

## 存储、调度和质量边界

- `bars`：已收盘历史，仍只追加版本。批量读取已有版本，再批量写入；OHLCV 未变化不生成新版本，旧观测不能覆盖较新版本。新增版本使用实际接收时间，不把补录时间伪装成历史收盘时间。
- `market_live_candles`：每个标的、周期至多一行可变展示缓存。校验 OHLC、时间范围和观测顺序；`is_final=false`，不进入指标预览、回测输入或冻结交易证据。
- `market_sync_state`：持久保存活跃状态、历史覆盖、待补数量、下次尝试时间、最近实时成功时间、失败代码。多用户同一标的/周期去重采集；不保存用户密钥或用户身份。自选价格查询另外按当前租户及用户过滤。
- 每轮最多 16 个到期实时请求、2 个串行历史页；历史页最多 900 根。轮询配置 5 秒，但实际刷新受上游响应及订阅规模影响，不构成 5 秒 SLA。最新请求仅重叠最近 3 根，历史补齐根据已落库数据重新计算最近缺口，进程重启可续采。
- 普通实时错误按 5–300 秒指数退避；历史错误 60 秒后重试；内部缺口无数据 5 分钟后复查；更早历史无数据标记 `SOURCE_LIMIT`，6 小时后复查，而非声称永久无历史。
- 429 的 `Retry-After` 转为持久等待时间，不阻塞线程睡眠、不无限重试；订阅新增、移除及进程重启不能绕过仍有效的源级等待。无效或不可表示的头使用 30 秒默认值。
- REST 收盘判定仍有 `EXCHANGE_FINALITY_ASSUMED` 标记；补录另标 `HISTORICAL_BACKFILL`，两者阻止 LIVE 资格。记录真实接收时间不等于证明交易所当时已最终确定该版本。
- 本轮不删除既有历史缓存，也不抹去旧质量标记或重算旧报告。回测任务上限仍为 5000 根；8000 是后台预取窗口，不能把 K 线数量当作独立交易样本数。

## 网页及接口

`GET /api/v2/bars` 新增 `cache`：同步状态、历史覆盖、最近采集时间和独立 `live_bar`。历史 `items` 仍只含已收盘 K 线，兼容既有调用。

`GET /api/v2/research/coverage` 附带同一缓存状态；回测表单每 10 秒刷新覆盖，不再只显示提交时的一次数量。

`GET /api/v2/market/watchlist-cache` 返回当前用户自选的价格、时间及同步状态。响应没有他人的自选列表或身份。

浏览器只用有界的内存缓存（最近 8 组币种/周期，每组最多 1500 根），不持久保存凭据。刷新浏览器后从服务器持久缓存恢复。增量合并保留版本单调性及整段数据的质量标记。

## 实际数据验收

本轮生产采集达到下列最近窗口覆盖；后台仍持续前进，后续数量可变化。

| 标的 | 1m / 5m / 15m / 30m / 1h / 4h | 8h | 1d |
| --- | --- | --- | --- |
| BTC_USDT | 每周期连续 8000 根 | 7462 根，暂达上游边界 | 2487 根，暂达上游边界 |
| ETH_USDT | 每周期连续 8000 根 | 7456 根，暂达上游边界 | 2485 根，暂达上游边界 |

两个标的共 16 个周期组合，16 行形成中缓存。现场观察实时成功时间约距当前 0–11 秒。API 数据库角色实际读取缓存成功，重启 market worker 后覆盖与继续采集状态保留。

上游请求分页遵循 [Gate 合约 K 线文档](https://www.gate.com/docs/developers/apiv4/en/futures/)；成交量叠加采用 [Lightweight Charts 官方示例](https://tradingview.github.io/lightweight-charts/tutorials/how_to/price-and-volume) 的独立价格尺度，不能与价格数值共用尺度。

## 测试与部署

- 193 项 Python 单元测试、23 项 PostgreSQL 集成测试、28 项前端测试通过。新增真实数据库的缺口修复规划、版本幂等、当前 K 线隔离、订阅持久等待和同租户用户隔离检查。
- 1440px / 390px 浏览器专项：慢请求不重叠、旧周期迟到响应不能覆盖新图、切回命中缓存、增量轮询不截断历史、形成中数据不进入指标请求、断网保留旧图及联网恢复、按钮不遮挡价格。浏览器回归拦截网络，不发生产通知或订单。
- 全模块回归覆盖导航、分页、弹窗、失败提示、角色边界及设置提交流程。实际 Gate 的 BTC 30m / 8h GET 查询也已成功。
- 升级前已生成权限 0600 的 PostgreSQL 备份，存于受限运行秘密目录，未输出凭据。迁移仅新增状态表/展示缓存表及调整订阅函数。
- 首次发布出现过一次 API 启动失败：旧 Vite 构建清空 `web/dist/assets` 与 API 启动重叠。systemd 已自动恢复。随后将 `npm run build` 改为暂存构建和原子发布，新增发布单测验证不完整构建不替换入口、旧资源仍保留；后续构建不再清空服务目录。
- 可用内存现场约 0.8–1.1 GB，磁盘剩余约 43 GB；未增加常驻进程。此结果不是多用户容量压测。追加历史和保留旧静态资源仍需后续容量监控/归档策略，不在本轮自动删除。
- 收尾实测：12 组 `READY`、4 组 `SOURCE_LIMIT`，最新采集距当前 3–4 秒；ETH 1h 研究读取实际可用 5000 根。数据库约 363 MB、可用内存 946 MB，公网 `/health/ready` 为 ready / database ok，公开页面引用资产与最终构建一致；原子发布后的检查没有新增 API 重启。

后续部署先运行迁移和测试，再执行 `npm run build --prefix web`，最后仅在后端代码变化时重启相应服务并检查 `/health/ready`。不要恢复使用直接在服务目录执行的清空式构建命令。
