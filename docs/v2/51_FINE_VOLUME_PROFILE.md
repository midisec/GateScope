# VPVR 细周期数据升级

日期：2026-09-15。状态：11:44 CST 完成前后端生产发布，上线后浏览器验收通过。本文件替代 50 号文档中“正式行情仅使用当前图表周期计算 VPVR”的说明；Coinglass 精选指标与其单位规则不变。

## 1. 交付边界

正式行情 VPVR 改为服务器细周期计算，默认优先使用已有 `1m` 缓存。可视区间、价格分层与价值区比例决定请求；浏览器只接收最多 96 个价格桶、POC、VAH、VAL 和来源/覆盖元数据，不下载全年分钟序列。

这仍是 **细周期 OHLCV 估算，不是逐笔成交统计**。每根源 K 线内依旧按高低价区间均匀分摊，但不再用一个小时或一天的大价格区间代替其内部所有分钟成交。单纯增加分层数量不会恢复逐笔成交事实。

例如同样 3 天可视区间，1 小时图的 72 根大 K 线可以使用 4,320 根分钟数据计算。时间粒度细了 60 倍，不代表计算误差或交易胜率改善 60 倍。1 分钟主图已经处于本轮最小源周期，不能声称它也获得了更细数据。

本轮复用后台持续采集的本地 K 线；不新增上游查询、不下载逐笔归档、不复制年度历史或写入新的数据库表。按可视区生成的少量价格桶在进程内短暂缓存，不增加长期硬盘数据。

## 2. 固定选源与真实覆盖

从 `1m / 5m / 15m / 30m / 1h / 4h / 8h / 1d` 中选择同时满足以下条件的最细周期：

- 不粗于主图周期。
- 请求区间完整源时间槽不超过 50,000 根。
- 请求时间跨度不超过 366 天。

选源只根据区间与预算，**不因分钟数据缺失而改用小时数据凑成 100%**。返回 `used_bars / expected_bars`，缺口、非法值、未收盘和单位无法确认的样本不补零。`coverage` 是时间槽覆盖率，不是成交量覆盖率、预测置信度或计算准确率。

示例（边界对齐、对应历史可用时）：

| 图表查询范围 | 底层周期 | 预计源样本 |
| --- | --- | --- |
| 3 天，1h 图 | 1m | 4,320 |
| 30 天，4h 图 | 1m | 43,200 |
| 180 天，1d 图 | 15m | 17,280 |

1m 图若请求超过 50,000 根，不擅自选择更粗周期，返回明确的缩小范围提示。半根边界、未来尚未收盘部分也会标记不完整；零成交量不生成虚构的 POC。

不足 100% 的覆盖不能四舍五入成 100%。例如 `17279/17280` 显示约 `99.994% · 部分数据`，页面与 PNG 使用同一格式。

## 3. 时间、修订与单位

请求使用实际可视、已收盘主图 K 线的首个开盘和最后收盘时间，构成 UTC 半开区间 `[from_time, to_time)`。不能用数组索引乘周期推算带有历史缺口的时间，也不能将细周期时间点插入主图时间轴而移动已有形态线。

数据库按目录中的精确 `instrument_id / venue / market / timeframe` 查找。在当前请求的服务端时间下，先选最新已知修订，再验证收盘、时长、OHLCV、可用时间和来源；不能因最新修订无效而重新启用旧的最终版本。响应原样回显请求范围，实际截断时间另外返回。

本接口是“当前查询时看到的历史数据”，没有历史 `as_of` 参数，不能将后来补录或修订的数据假装成历史当时已知的交易证据。它不改写形态预测、不提高原有置信度、不产生订单或通知。

横柱保留同一源序列的相对分布，不给未知单位贴 USD/币数量标签。现有 Gate 现货 REST 适配器保存报价币成交额，而旧现货归档单位尚未验证一致；本功能对 SPOT 仅接纳明确 REST 来源，排除未核实的归档/旧来源，返回 `SOURCE_VOLUME_UNIT_UNVERIFIED`，不能连“占比”也直接混加。合约数据源的张数不能擅自按当前合约乘数换算全部历史。[Gate 现货文档](https://www.gate.com/docs/developers/apiv4/en/spot/)、[Gate 合约文档](https://www.gate.com/docs/developers/apiv4/en/futures/)

## 4. 接口、交互和资源上限

登录后的只读接口：

```text
GET /api/v2/market/volume-profile
  ?instrument_id=<UUID>
  &timeframe=1h
  &from_time=<Unix秒>
  &to_time=<Unix秒，右端不含>
  &rows=48
  &value_area=70
```

版本 `fine-ohlcv-profile-1`。响应包含精确查询绑定、`source_timeframe`、`source_step_seconds`、`expected_bars`、`used_bars`、`coverage`、`quality_flags`、`generated_at`、`expires_at` 和 `profile`。顶层状态为 `AVAILABLE / PARTIAL / NO_DATA / ZERO_VOLUME`；部分数据有有效分布时允许画图但显式标记，不回退为旧粗周期结果。

- SQL 事务只读，语句超时 5 秒、锁等待 1 秒；范围与索引约束先于排序，最多 50,000 个完整源槽。
- 数学计算为两遍扫描加区间差分累计，近似 `O(n log bins + bins)`；缩放与补偿求和控制浮点误差，保持成交量守恒，无法表示的量保留标记而非输出 Infinity/假零。
- 单 API 进程最多 2 个计算任务，64 个结果、最多 30 秒缓存；同键进行中的请求不重复计算，繁忙返回 `Retry-After`。这些是进程级约束，并非跨服务器分布式限流。
- 每用户每分钟 60 次；仍遵守原登录/MFA边界。错误不返回 SQL、数据库地址或凭据。
- 前端 350ms 防抖、取消旧请求、用户/币种/周期/区间/参数完整绑定，最多 8 个短期缓存结果。改变宽度仅重绘，不重新查询；页面隐藏暂停读取。
- 429 按 `Retry-After` 等待，最多一次自动重试，之后需手动重试；503 等错误明确显示，不把旧币种或旧范围的分布留在新图上。
- 主图 primitive 使用真实价格轴转换，支持对数轴和设备像素比。PNG 保留来源周期、估算与部分覆盖标识。

原“精选指标”入口和布局参数不变，已保存 VPVR 配置自动使用新数据路径。首次使用或拖动时显示读取状态；不静默改成粗周期估算。

## 5. 验证记录

初次真实数据库检查只读使用 API 数据库角色；在进程内路由中注入诊断身份，不等于生产登录验证。最终生产登录与浏览器验收另行记录。

| 真实样本 | 来源与覆盖 | 首次计算 / 缓存命中 |
| --- | --- | --- |
| BTC、ETH、SOL、龙虾合约，各最近 3 天 | 1m，全部 4,320 / 4,320 | 192–236ms / 4ms |
| BTC 最近 180 天 | 15m，17,279 / 17,280，PARTIAL | 1,524ms / 4ms |

上述是该次采样结果，不代表所有历史区间无缺口，也不是性能 SLA。

复验相同查询时，四个最近 3 天区间首次计算为 204–239ms、缓存 4–5ms；180 天区间为 873ms、缓存 5ms，缺失槽计数保持一致。OpenAPI 与发布前契约比较未发现破坏性变更，新路径只读且保留 SessionCookie 登录要求。

接近预算上限的追加真实检查：BTC 最近 34 天选择 `1m`，预计 48,960 根，实际有效 45,157 根，覆盖 `92.2324346%`、`PARTIAL`，首次 2,925ms / 缓存 6ms。这个长区间存在 3,803 个缺失/不合格槽，不能将近期 3 天的完整结果外推到整个历史。接口仍保留固定分钟来源与真实分母，不用更粗 K 线掩盖缺口。

浏览器验收不是只看按钮可点击或文件可下载：初版脚本虽然取得 PNG，但人工检查发现导出时的同步重布局会清空远端 VPVR 层。现已增加 PNG 实际像素检查（价值区与 POC 柱），旧版本在此检查明确失败；必须修复并通过后才能作为最终导出验收。Coinglass 全指标渲染场景使用明确的受控夹具，与真实缓存/OI检查分开，不宣称上游所有系列实时可用。布局保存请求在浏览器内存拦截，不覆盖用户配置。

## 6. 逐笔成交阶段的边界

Gate 官方确实提供成交月度归档；本轮没有接入，不应说它不存在，也不应承诺任意币种每个月都有完整数据。[Gate 历史数据](https://www.gate.com/zh/developer/historical_quotes)

若后续实现真正成交价归档，应独立设计受限下载、交易 ID 去重、断点补录、逐分钟覆盖清单、价格桶压缩与冷存储。不能把现在的 K 线归档限制直接无限放大，更不能在未核实单位/重复记录/缺失交易的情况下标记“逐笔精准”。
