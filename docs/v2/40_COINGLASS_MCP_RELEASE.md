## 2. 数据与权限边界

严格匹配交易所、市场类型、币种、报价币、结算币及供应商合约符号；龙虾等中文符号保留，禁止相似名称猜测。Coinglass 不借用其他用户配置；MCP 不能读取供应商密钥或账户信息。缺失、过期、未闭合、周期/单位未知均明确表示，不补零、不插值。

已经接入 USD 持仓量、账户多空比、实际多空爆仓金额。资金费率单位尚未核实，保持 UNKNOWN，数值不展示且后台跳过无效采集。爆仓金额不是未来价格分布，持仓 USD 变化不等于净多资金流入。

形成中的 NEXT_PIVOT 仍为下一拐点候选区，不变成止盈目标。Coinglass 只提供当前证据和独立用户观察情景；不覆盖原预测、历史评分或胜率。保存的研判追加且不可修改，包含原结构、实际证据版本、数据来源和采集时间。旧页面打开研判时可读取最新结构并提示证据变化；保存用户情景仍检查证据冲突，不能静默套用新形态。

后台采集与 Web/API 分离。Coinglass 默认预热自选的默认周期，网页额外请求的周期按近期访问优先、保温两小时。自选 K 线原有八周期后台采集不受影响。调度保留配额余量，源请求间隔和整批间隔有界；429 停止本轮后续调用并尊重 Retry-After。当前数据状态可能 PARTIAL/STALE，不承诺所有币种八周期的 Coinglass 同时实时更新。

## 4. 发现并修复的生产问题

1. **MCP 最新 K 线查询慢**：旧无范围读取可能排序全年历史。现在先定位最新时刻，按最近 N 个日历周期限定查询，精确绑定 venue/market 并匹配已有索引；最新时刻和最新段查询均有 5 秒事务局部超时。真实缺口仍可见，不向更老历史扩充来凑数量。
2. **数据库软内存限额导致回收抖动**：主机仍有可用内存，但 PostgreSQL 原 MemoryHigh=2G、MemoryMax=2500M 导致高内存压力和 504。恢复后持久化为 3G/3500M，保留总量上限与自动恢复，不重启数据库或清空数据。终验主机约 4.5 GB 可用，负载约 1.3，9 个应用服务 active，健康检查 200。
3. **BTC 实际缺一根 1m K 线**：从 Gate 只读取限定三分钟窗口，核实并只补该缺失时刻的一根真实数据，标记真实采集时间。没有生成假 K 线或改写原始历史预测。
4. **缓存 GET 消耗研判 POST 配额**：拆分用户/方法限流桶，避免正常轮询让首次研判返回 429。
5. **缓存过期格式**：旧入库 expiry 含小数，而规范要求整数秒，导致未过期研判被判断 SNAPSHOT_STALE。新采集写整数，旧缓存读取向下取整兼容；不改动已保存的不可变研判。
6. **结构证据更新后查看冲突**：初次查看允许读取并标明最新证据；情景保存继续保留冲突检查。
7. **Coinglass 配额浪费和手机布局**：取消全八周期无差别预热、隔离未知资金费率采集；修复长客户端名导致的手机横向溢出。
