## 已部署修改

### 1. 历史任务独立容量准入

`StoragePressureGuard` 接入 strategy 与 research 两个 worker：

- 默认空闲小于 **3 GiB** 暂停历史任务，暂停后必须超过 **5 GiB** 才恢复，避免阈值附近反复开关。
- 每 15 秒检查一次；可用空间未知、路径无法验证或配置错误时，仅拒绝历史任务准入。
- strategy 继续规则扫描和 `track_slice()`，只暂停历史 `schedule()` / `run_slice()`。
- research 暂不领取新的指标、结构和组合回测计算；不把等待中的任务改成失败或完成。
- worker 保持运行并上报 `history_state`，健康检查不会把正常暂停当成进程故障重启。
- 不停止 market、PAPER、通知和 MCP 服务，也不把数据库设为只读。

这是任务/分片开始前的准入，不是磁盘预留，也不强行中断已经开始的长回测。
进程重启会重新建立阈值状态；手动配置开关的变化需要重启对应进程。

| 配置 | 默认/用途 |
| --- | --- |
| `GATESCOPE_HISTORY_TASKS_ENABLED` | `true`；`false` 明确暂停历史任务 |
| `GATESCOPE_HISTORY_PAUSE_FREE_GIB` | `3` |
| `GATESCOPE_HISTORY_RESUME_FREE_GIB` | `5`，须大于暂停阈值 |
| `GATESCOPE_HISTORY_CHECK_SECONDS` | `15` |
| `GATESCOPE_HISTORY_STORAGE_PATHS` | 运营者已核验的本地挂载路径，冒号分隔 |
| `GATESCOPE_HISTORY_REMOTE_DB_CAPACITY` | 远程库必须由外部监测并明确设置 `EXTERNALLY_MONITORED`；不是自动测量远程磁盘 |

应用盘始终检测。本机 PostgreSQL 未显式配置路径时尝试检测 data/WAL；权限不足不会扩大数据库角色权限。
本次以 root 核验应用、`/var/lib/postgresql/14/main` 和 `pg_wal` 都属于根分区设备 64515，
故给两个服务安装 `60-storage-budget.conf`，指定可被服务用户读取的挂载根 `/`。
数据库迁移至其他分区/独立 WAL/表空间时，必须重新核验并更新路径，不能继续沿用这个部署假设。

### 2. 无新 K 线不重写完整状态

实时形态跟踪先检查是否存在新的、已收盘且当时已可用的 K 线。
没有新数据时只更新小型调度时间，不重写包含原始几何、预测及学习数据的完整检查点。
原始快照时间和已有错误状态保留；新 K 线失败或时间预算耗尽不会提前保存历史学习结果。

发生真实模型切换或新 K 线时仍走原有生命周期规则，不跳过停机期间的失败判断。

### 3. 同内容阶段/收益不重复 UPDATE

为阶段和收益 UPSERT 添加逐列 `IS DISTINCT FROM` 条件，仅比较原本允许变化的列。
相同输入不再生成新的行版本，减少 WAL、TOAST 及索引写放大。
首次预测、采样口径、样本归属及负收益仍保留；真实结果变化仍正常更新。

本项不等于跨事件完整快照去重，也不会立即缩小既有数据库文件。

### 4. 页面展示实际暂停状态

`/api/v2/patterns/watchlist-progress` 增加 `replay_control`，只包含允许的状态和心跳时间。
不向普通用户输出服务器路径、连接串或其他用户信息；自选数据隔离不变。
心跳过期超过 90 秒、工作进程停止或读取异常返回 `UNKNOWN`。

自选历史弹窗显示容量暂停原因并保留进度，已完成报告仍显示完成。
刷新失败或状态未知时显示“当前状态待确认”，不会将旧 `RUNNING` 误报为正在处理。

### 5. 系统日志容量上限

安装 `/etc/systemd/journald.conf.d/60-gatescope-storage-budget.conf`：
系统日志目标上限 256 MiB、单文件 32 MiB、最长 7 天、保留空间目标 2 GiB，临时日志上限 64 MiB。
实际占用可因活动日志和文件粒度略高于上限；这不是应用数据库的磁盘配额。
数据库内审计和交易事件不适用此日志留存设置。

## 维护工具安全补强

`scripts/compact_structure_storage.py` 现在分别检查应用、实际 PostgreSQL 数据目录与 WAL 目录，
跟随真实挂载/符号链接；任意路径无法确认或低于 2 GiB 都拒绝执行。
服务器地址使用 `host(inet_server_addr())` 并兼容 inet 的 CIDR 表示和 IPv4-mapped IPv6，
只承认实际回环/本地 socket，不放宽对远程库的拒绝。不能通过 SSH 转发冒充本机维护。

- dry-run 使用只读事务、不占维护互斥锁、不更新进度。
- 批次支持 `--batch-rows 1..32`，低空间/错误整批回滚，成功 COMMIT 后才计数。
- 阶段摘要在写前和写后按真实事件引用还原校验 SHA-256 与原始预测。
- 明确区分表示层估算节省与物理回收量；不承诺 `df` 立即下降。

本次生产 events/stages 两种模式各试运行 `--max-rows 32 --seconds 10 --batch-rows 8`，
都返回 **`PAUSED_LOW_DISK`，scanned=0、packed=0、committed_batches=0、apply=false**。
三处实测空闲约 1,747,099,648 字节，正确拒绝历史重写；没有绕过安全门槛。
